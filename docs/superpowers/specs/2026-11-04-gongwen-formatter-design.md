# 公文排版 设计文档

日期：2026-11-04
状态：待用户审阅

## 1. 目标

一个单独的 Windows 桌面软件「公文排版」：把已有 Word 或粘贴的文字，一键排成本单位公文格式（来自用户的 unit-doc-format skill），先预览、可修改，再导出 .docx。

**成功标准**

- 解压后双击 `公文排版.exe` 即可使用，无需安装 Python。
- 拖入 .docx 或粘贴文字 → 自动识别每段类型 → 左侧可改类型/文字/删段，右侧 A4 实时预览 → 导出 .docx。
- 导出的 .docx 在用户电脑（装有方正小标宋、仿宋_GB2312、楷体_GB2312、黑体）上打开即为单位格式，各项参数与第 4 节一致。

**不做（第一版）**

- 读取老格式 .doc（提示先转换或粘贴文字）。
- AI 根据要点代写正文。
- 保留原文档里的图片、批注、修订、脚注。
- 与文件转换器合并；macOS / Linux 发布。

## 2. 方案

与文件转换器同一套技术：Python + pywebview（Edge WebView2）+ 原生 HTML/CSS/JS + PyInstaller，GitHub Actions 在 Windows 上打包。代码放在同一仓库的独立目录 `gongwen/`，单独打包、单独下载，两个软件互不依赖。

不需要 LibreOffice：读写 .docx 只用 python-docx。

## 3. 架构

```
gongwen/
├─ core/
│  ├─ model.py      数据结构：Block、Document
│  ├─ reader.py     .docx / 粘贴文字 → 段落列表（含表格）
│  ├─ classify.py   识别每段类型 + 判断文种
│  ├─ dates.py      中文数字日期 → 阿拉伯数字
│  └─ build.py      Document → 单位格式 .docx（排版逻辑取自 skill 的 gw_build.py）
├─ api.py           JS 桥：open_docx / parse_text / export / pick 对话框 / open_file
├─ main.py          入口 + --selftest
└─ web/             index.html、style.css、app.js
```

`core/` 不依赖界面，可单独测试。

### 3.1 数据结构

```
Block  = { "t": 类型, "text": 文字 }，表格为 { "t": "table", "rows": [[...], ...] }
类型   = title | addressee | h1 | h2 | h3 | body | attachment | signer | date | table
Document = { "kind": "notice" | "brief", "blocks": [Block, ...] }
```

界面与后端之间传的就是这个结构（JSON）。附件块的 `text` 为去掉原序号后的附件名；导出时由程序在前面单独输出“附件”一行，再按顺序编号“1、”“2、”。

### 3.2 读入

- **.docx**：按文档顺序遍历 body 里的段落和表格。表格 → `table` 块（每格取纯文字，合并单元格按 python-docx 读到的内容原样保留）。段落 → 文字。
- **粘贴文字**：按换行拆成段落；`\r\n` 和 `\r` 视为换行。
- **清理（两种输入都做）**：去掉空行；去掉段首段尾的半角/全角空格、制表符；文字内部一字不改。

### 3.3 识别规则（按顺序判断，先命中者为准）

令 `SHORT = 30` 字，`TITLE_MAX = 40` 字，`h_max = 50` 字。

1. **标题**：第 1 个非表格段落 → `title`。紧接其后的第 2 段，若长度 ≤ TITLE_MAX、不以 `。；，：:！？` 结尾、不以任何序号开头 → 也是 `title`（最多 2 行）。
2. **主送机关**：标题后的第一段，若以 `：` 或 `:` 结尾、长度 ≤ SHORT、不含 `。` → `addressee`。
3. **附件**：文字为 `附件` / `附件：` / `附件:` 的段落进入附件区；其后每个以序号（`1、` `1.` `1．` `（1）`）开头的段落 → `attachment`，去掉序号；遇到第一个不带序号的段落即结束附件区。`附件：XXX`（同一行带内容）→ 单个 `attachment`，text 为 `XXX`。“附件”这一行本身不保留为块（导出时自动生成）。
4. **日期**：最后一个非表格段落若整段匹配日期（阿拉伯数字 `\d{4}年\d{1,2}月\d{1,2}日` 或中文数字 `[〇零一二三四五六七八九]{4}年…月…日`）→ `date`。
5. **落款**：日期前一段若长度 ≤ 20、不以 `。；，：:` 结尾、未被识别为其他类型 → `signer`。
6. **序号标题**（对其余段落）：
   - `^[一二三四五六七八九十]+、` → `h1`
   - `^[（(][一二三四五六七八九十]+[）)]` → `h2`
   - `^\d+[、.．]` 或 `^[（(]\d+[）)]` → `h3`
   - 但若长度 > h_max 且以 `。` 结尾 → `body`（这是一整段话）。
   - “一是……”“二是……”不是标题 → `body`。
7. 其余 → `body`。

**文种**：有 `addressee` → `notice`，否则 → `brief`。用户可在界面切换。

### 3.4 日期规范化

导出时 `date` 块若为中文数字，转为阿拉伯数字：`二〇二六年八月二十四日` → `2026年8月24日`。年份逐位转换（〇/零→0）；月、日按“十”的位置转换（十→10，十二→12，二十四→24，三十一→31）。无法解析时原样输出。

### 3.5 排版输出（build）

沿用 skill 的 `gw_build.py` 参数（第 4 节），由 Document 生成：

- `title` 块依次输出为标题行；`brief` 时标题后加一个空行。
- `addressee`、`h1`、`h2`、`h3`、`body`、`table` 按顺序输出。
- 所有 `attachment` 块收集后，在正文之后、落款之前输出：“附件”一行 + 每项 `{i}、{名称}`。
- `signer` / `date`：前空一行，右对齐。
- 文种为 `brief` 时仍输出用户保留的 `addressee`/`signer`/`date` 块（以用户在左侧的选择为准），只有“标题后是否空行”随文种变化。

### 3.6 界面

单窗口，三部分：

1. **顶栏**：「打开 Word」（也支持把 .docx 拖进窗口）、「粘贴文字」（弹出大文本框，点「识别」）、文种单选（通知 / 信息简报）、「导出 Word」。
2. **左栏 段落列表**：每行 = 类型下拉框（标题、主送机关、一级标题、二级标题、三级标题、正文、附件、落款、日期）+ 可直接编辑的文字 + 删除按钮。表格行显示“表格（N 行 × M 列）”，类型不可改，可删除。
3. **右栏 实时预览**：按 A4 比例缩放显示，字体名、字号、行距、缩进、对齐与导出一致（CSS `font-family` 使用同名字体）。左栏任何修改立即刷新；点左栏某段，预览中对应段落高亮并滚动到可见。

导出：弹出保存对话框，默认文件名为标题各行拼接（去掉文件名非法字符 `\/:*?"<>|`），扩展名 .docx；已存在时由系统对话框询问覆盖。导出成功后显示「打开文件」按钮。

未导入内容时，左栏显示“打开一份 Word，或粘贴文字开始”。

## 4. 单位公文格式参数（取自 skill，原样实现）

| 要素 | 字体 | 字号 | 对齐 / 缩进 |
|---|---|---|---|
| 标题 | 方正小标宋简体 | 二号 22pt | 居中，不缩进 |
| 主送机关 | 黑体 | 三号 16pt | 两端对齐，顶格 |
| 正文 | 仿宋_GB2312 | 三号 | 两端对齐，首行缩进 2 字符 |
| 一级标题 | 黑体 | 三号 | 首行缩进 2 字符 |
| 二级标题 | 楷体_GB2312 | 三号 | 首行缩进 2 字符 |
| 三级标题 | 仿宋_GB2312 | 三号 | 同正文 |
| 附件 | 仿宋_GB2312 | 三号 | “附件”一行 + 每项一行，均首行缩进 2 字符 |
| 落款、日期 | 仿宋_GB2312 | 三号 | 右对齐，前空一行 |
| 表格 | 表头黑体、内容仿宋_GB2312 | 四号 14pt | 全框线、居中、单倍行距、表后空一行 |
| 页码 | 默认 | 小五 9pt | 页脚居中，只写数字 |

- 全部段落：行距固定 26 磅，段前 0，段后 8 磅；全文不加粗；四个字体槽（ascii/hAnsi/eastAsia/cs）设为同一字体。
- 页面：A4；上下 2.54cm，左右 3.17cm；页眉 1.5cm，页脚 1.75cm；文档网格按行，跨度 15.6 磅（linePitch 312）。
- 中文排版设置：eastAsia 语言 zh-CN，标点挤压，兼容模式 15（同 skill 脚本）。

## 5. 错误处理

- 可预期错误抛 `GongwenError(中文提示)`，界面以提示条显示：
  - 选中 .doc：“暂不支持老版 .doc 文件，请先用「文件转换器」转为 .docx，或复制文字后点「粘贴文字」”。
  - .docx 损坏/不是 Word：“文件已损坏或无法读取”。
  - 文档里没有文字：“没有读到任何文字”。
  - 导出时文件被占用（Word 正打开着）：“文件正在被其他程序使用，请先关闭它或换个文件名”。
- 未预期异常写入日志 `%LOCALAPPDATA%/公文排版/logs/app.log`，界面显示“操作失败：<异常类型>”。

## 6. 测试

- **识别（pytest）**：用 skill 中两份范本的结构（通知、信息简报）做端到端用例；逐条覆盖 3.3 的每条规则及反例（长序号段落判为正文、“一是”判为正文、两行标题、附件区结束、日期前的落款、表格不参与标题判断）。
- **日期规范化**：`二〇二六年八月二十四日`、`二〇二六年十月一日`、`二〇二六年十二月三十一日`、已是阿拉伯数字、无法解析。
- **读入**：生成含段落 + 表格的 .docx，检查顺序与清理；损坏文件、空文档报错；粘贴文字的换行与空行。
- **输出格式**：导出后用 python-docx 读回，断言第 4 节每项参数（字体四槽、字号、行距、段后、首行缩进 200 字符、对齐、页边距、docGrid、页码域、表格样式），以及附件编号、落款前空行、brief 标题后空行。
- **api 层**：假 window，测试 open/parse/export 返回值与错误信息。
- **界面**：Playwright 冒烟测试（假后端）：导入、改类型后预览字体变化、删除段落、切换文种、导出按钮状态；截图。
- **打包**：CI 在 Windows 打包后，给 DLL 打“来自 Internet”标记，运行 `公文排版.exe --selftest`（加载 pythonnet + 把一段示例文字排版导出），确认成功。
